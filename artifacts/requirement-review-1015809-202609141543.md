## Scope

Функциональность «Заявка на отпуск»: страница личного кабинета сотрудника (раздел «Отпуска»), позволяющая просматривать данные сотрудника, остаток отпуска за рабочий год и список заявок, подавать заявку с авторасчётом количества календарных дней и управлять её статусами. Роли: Сотрудник (подаёт заявку), Руководитель (согласует), HR (контролирует), Администратор (настраивает). Учётный период — рабочий год (индивидуально для каждого сотрудника), базовая норма — 28 календарных дней ежегодного оплачиваемого отпуска.

## Requirements

| ID | Требование |
|----|-----------|
| FR-01 | Система отображает данные сотрудника: ФИО, подразделение, должность, руководитель |
| FR-02 | Система отображает остаток отпуска: всего положено за рабочий год (28 к.д.), использовано, запланировано (поданные/утверждённые заявки), доступно для подачи новой заявки |
| FR-03 | Система отображает список предыдущих заявок за текущий рабочий год с указанием дат, количества дней и статуса |
| FR-04 | Форма содержит обязательные поля: тип отпуска (ежегодный оплачиваемый, дополнительный, без сохранения з/п и т.п.), дата начала (дд.мм.гггг), дата окончания (дд.мм.гггг); опциональные: комментарий, прикреплённый файл |
| FR-05 | Поле «Количество календарных дней» рассчитывается автоматически и недоступно для ручного редактирования |
| FR-06 | Кнопки формы: «Сохранить черновик», «Отправить», «Отмена» |
| FR-07 | При нажатии «Отправить» заявка переходит в статус «На согласовании» и направляется руководителю |
| FR-08 | При нажатии «Сохранить черновик» заявка сохраняется в статусе «Черновик» и не участвует в расчёте остатка |
| FR-09 | Статусы заявки: Черновик, На согласовании, Утверждена, Отклонена, Отменена |
| FR-10 | Руководитель может утвердить или отклонить заявку с указанием причины |
| FR-11 | Сотрудник получает уведомление при изменении статуса заявки |
| FR-12 | Утверждённая заявка передаётся в HR-систему для оформления приказа |
| FR-13 | Сотрудник может отменить заявку до статуса «Утверждена» |

## Business Rules

| ID | Правило |
|----|---------|
| BR-01 | Если дата начала — понедельник, а дата окончания — пятница, то количество дней отпуска = 7 календарных дней (учитываются следующие за пятницей суббота и воскресенье) |
| BR-02 | В остальных случаях количество дней = (дата окончания − дата начала) + 1 календарный день |
| BR-03 | Контрольные примеры: 01.07.2024 (Пн)–05.07.2024 (Пт) → 7; 01.07.2024 (Пн)–07.07.2024 (Вс) → 7; 03.07.2024 (Ср)–05.07.2024 (Пт) → 3 |
| BR-04 | Нерабочие праздничные дни (при наличии) не включаются в число календарных дней отпуска, если это предусмотрено законодательством и настройками системы |
| BR-05 | Минимальное количество дней отпуска — 1 календарный день |
| BR-06 | Максимальное количество дней по одной заявке не может превышать доступный остаток отпуска за текущий рабочий год |
| BR-07 | Суммарное количество дней по всем заявкам за рабочий год не может превышать 28 календарных дней |
| BR-08 | Дата окончания не может быть раньше даты начала |
| BR-09 | Дата начала, по умолчанию, не может быть раньше текущей даты (если иное не настроено) |
| BR-10 | Заявка не может пересекаться по датам с другими активными заявками сотрудника |
| BR-11 | Правило «хотя бы один отпуск ≥ 14 дней»: в течение рабочего года хотя бы одна заявка должна содержать не менее 14 календарных дней подряд; при отправке заявки система анализирует все заявки за год (черновики, на согласовании, утверждённые); если текущая заявка < 14 дней, нет других заявок ≥ 14 дней и после утверждения текущей заявки остаток станет < 14 — блокировка отправки с указанным сообщением; если остаток после заявки ≥ 14 — отправка разрешается |

## Acceptance Criteria

| ID | Критерий |
|----|----------|
| AC-01 | Период 01.07.2024 (Пн)–05.07.2024 (Пт) → «7 календарных дней» |
| AC-02 | Заявка на 0 дней → ошибка «Минимальное количество дней отпуска — 1» |
| AC-03 | Остаток 5 дней, заявка на 7 дней → ошибка «Недостаточно дней отпуска. Доступно: 5» |
| AC-04 | Заявка на 10 дней при остатке 18 → отправка разрешена (остаток ≥ 14) |
| AC-05 | Заявка на 10 дней при остатке 10, других заявок ≥ 14 нет → блокировка с сообщением о необходимости 14-дневного отпуска |
| AC-06 | Заявка на 14 дней при остатке 14 → успешно отправляется |

| VR-04 | Дата окончания ≥ даты начала (BR-08) |

| VR-06 | Отсутствие пересечений с активными заявками (BR-10) |
| VR-07 | Правило «хотя бы один отпуск ≥ 14 дней» (BR-11) |
| VR-08 | Авторасчёт количества дней, поле не редактируется (FR-05) |

## Dependencies

- Отображение данных и остатка (FR-01..FR-03) зависит от учётного периода (индивидуальный рабочий год) и нормы 28 дней.
- Авторасчёт дней (FR-05) зависит от правил BR-01..BR-04.
- Валидации (BR-05..BR-11) зависят от формы (FR-04) и авторасчёта (FR-05).
- Правило «≥ 14 дней» (BR-11) зависит от всех заявок за рабочий год (FR-03) и остатка.
- Смена статусов (FR-07..FR-10, FR-13) зависит от отправки заявки.
- Уведомления (FR-11) зависят от смены статусов.
- Передача в HR-систему (FR-12) зависит от утверждения заявки.

| AMB-05 | BR-11 учитывает «черновики, на согласовании, утверждённые»; судьба статусов «Отклонена»/«Отменена» в анализе не упомянута. |

## Positive Flows

| ID | Поток |
|----|-------|
| PF-01 | Сотрудник открывает раздел «Отпуска» → видит данные, остаток (положено/использовано/запланировано/доступно) и список заявок за рабочий год. |
| PF-02 | Сотрудник заполняет форму → система авторассчитывает количество дней (BR-01..BR-04) → проходит валидации → «Отправить» → статус «На согласовании», заявка направлена руководителю. |
| PF-03 | Руководитель утверждает заявку с причиной → статус «Утверждена» → сотрудник получает уведомление → заявка передаётся в HR-систему. |
| PF-04 | Сотрудник сохраняет черновик → статус «Черновик», заявка не влияет на остаток. |
| PF-05 | Сотрудник отменяет заявку до утверждения → статус «Отменена». |
| PF-06 | Правило «≥ 14 дней»: заявка < 14 дней при остатке после заявки ≥ 14 (или наличии заявки ≥ 14) → отправка разрешена. |

## Boundaries

| ID | Граница |
|----|---------|
| B-01 | Минимум: 1 календарный день (0 дней → ошибка). |
| B-02 | Максимум за год: 28 дней (сумма > 28 → блокировка; ровно 28 → допустимо). |
| B-03 | Заявка ровно на доступный остаток → допустима. |
| B-04 | Порог правила «≥ 14 дней»: остаток после заявки = 14 → разрешено; = 13 → блокировка. |
| B-05 | Расчёт: дата начала = дата окончания → 1 день; Пн–Пт → 7; Пн–Вс → 7; Ср–Пт → 3. |
| B-06 | Пересечение: окончание одной заявки = начало другой (трактовка не определена, AMB-06). |
