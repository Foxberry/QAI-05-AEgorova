## Scope

Функциональность «Расчёт и управление отгулами»: страница личного кабинета сотрудника / HR-портала, позволяющая просматривать доступный остаток отгулов, детализацию начислений и списаний, подавать заявку на отгул, отслеживать статус заявки и историю. Роли: Сотрудник (баланс, заявки, отмена черновика, история), Руководитель (баланс подчинённых, согласование/отклонение), HR (корректировки, правила, отчёты), Администратор (интеграции, коэффициенты, сроки сгорания, роли). Расчёт баланса выполняется на сервере по формуле Доступно = Начислено − Использовано − Зарезервировано.

## Dependencies

- Отображение баланса (FR-01..FR-04) зависит от серверного расчёта (FR-10..FR-17).
- Расчёт начислений зависит от интеграции с табелем учёта рабочего времени (FR-38).
- Проверка пересечений (FR-21) зависит от интеграции с кадровым учётом (FR-39).
- Проверка выходных/праздников (FR-22) зависит от корпоративного календаря (FR-40).
- Оформление заявки (FR-19) зависит от баланса и норм расчёта (FR-12..FR-15).
- Проверки перед отправкой (FR-20..FR-24) зависят от формы заявки (FR-19).
- Согласование (FR-26..FR-30) зависит от отправки заявки (FR-25).
- Уведомления (FR-31..FR-34) зависят от смены статусов и интеграции с системой уведомлений (FR-41).
- История и аудит (FR-35..FR-37) зависят от всех операций по заявкам и начислениям.
- Безопасность доступа (NFR-01) связана с ролями и SSO/LDAP (FR-42).

## Ambiguities

| ID | Описание |
|----|----------|
| AMB-01 | Значение «лимит подряд идущих отгулов» (FR-23) не задано числом — не определено, сколько подряд отгулов допустимо. |
| AMB-02 | Срок подачи (FR-24) указан как «например, не позднее 3 дней» — точное значение и привязка (до начала отгула? до/после даты?) не зафиксированы. |
| AMB-03 | Формат отображения баланса «в днях и часах» (FR-01) не специфицирован (например, «2 дн 4 ч»); единая единица отображения не определена. |
| AMB-04 | Коэффициент за работу в выходной/праздник «1.0 или 2.0 по политике» (FR-14) — не определено, какой коэффициент применяется в каких условиях. |
| AMB-05 | Проверка «если отгул только на рабочие дни» (FR-22) — не определено, когда отгул «только на рабочие дни», а когда может включать выходные. |
| AMB-06 | Правила сгорания отгулов не описаны: сроки сгорания, механизм, период уведомления до даты сгорания. |
| AMB-07 | Приоритет списания «сначала сгорающие, затем обычные» (FR-16) — поведение при частичном покрытии заявки из обоих пулов не специфицировано. |
| AMB-08 | «Массовые корректировки» HR (FR-33) — механизм, ограничения и права не описаны. |

## Conflicts

| ID | Описание |
|----|----------|
| CONF-01 | Раздел «Область и роли» ограничивает сотрудника правом «отменяет черновик» (FR-43), тогда как статусная модель (FR-26) включает терминальный статус «Отменено» после этапа «На согласовании». Неоднозначно, может ли сотрудник отменить заявку на этапе согласования или только черновик. Не разрешается самостоятельно — эскалация владельцу требований. |

## Positive Flows

| ID | Поток |
|----|-------|
| PF-01 | Сотрудник открывает страницу → видит Доступно (дни и часы), Начислено, Использовано, Зарезервировано, дату актуальности и предупреждение о сгорании при его наличии. |
| PF-02 | Сотрудник с Доступно > 0 нажимает «Оформить отгул» → выбирает тип, дату/период, количество (авторасчёт), комментарий, при необходимости файл-основание, согласующего → проверки пройдены → заявка отправлена → статус «На согласовании», баланс зарезервирован, руководителю направлено уведомление. |
| PF-03 | Руководитель одобряет заявку → зарезервированное становится использованным, баланс уменьшается, сотрудник получает уведомление. |
| PF-04 | Руководитель отклоняет заявку с комментарием → резерв снимается, сотрудник видит причину и получает уведомление. |
| PF-05 | Сотрудник просматривает таблицы начислений и списаний с фильтрами (период, тип, статус), сортировкой по дате, пагинацией/подгрузкой. |
| PF-06 | Сотрудник/HR/администратор просматривает историю действий (аудит) в соответствии с ролью. |

## Negative Flows

| ID | Поток |
|----|-------|
| NF-01 | Доступно < запрошенного → отправка блокируется, показывается понятная ошибка. |
| NF-02 | Дата/период пересекаются с отпуском, больничным или командировкой → ошибка, отправка блокируется. |
| NF-03 | Дата — выходной/праздник (отгул только на рабочие дни) → ошибка, отправка блокируется. |
| NF-04 | Превышен лимит подряд идущих отгулов → ошибка, отправка блокируется. |
| NF-05 | Нарушены сроки подачи → ошибка, отправка блокируется. |
| NF-06 | Доступно = 0 → кнопка «Оформить отгул» неактивна. |
| NF-07 | Сотрудник пытается просмотреть данные другого сотрудника → доступ запрещён. |
| NF-08 | Руководитель видит баланс только своих подчинённых. |

## Boundaries

| ID | Граница |
|----|---------|
| B-01 | Доступно = 0: кнопка «Оформить отгул» неактивна; Доступно > 0: активна (граница 0). |
| B-02 | Запрошенное количество = Доступно: отправка разрешена (равенство допустимо). |
| B-03 | Запрошенное количество > Доступно: отправка блокируется. |
| B-04 | Округление: до 0.5 дня или до 1 часа (в зависимости от настройки). |
| B-05 | Норма: 8 часов = 1 рабочий день (конвертация часов в дни). |
| B-06 | Сгорание: предупреждение до даты сгорания; приоритетное списание сгорающих. |
| B-07 | Срок подачи: не позднее 3 дней (значение уточняется, AMB-02). |

## Risks

| ID | Риск |
|----|------|
| R-01 | Ошибки в расчёте баланса приводят к финансовым/юридическим последствиям (некорректные выплаты за отгулы). |
| R-02 | Неверный приоритет списания может привести к потере сгорающих отгулов сотрудником. |
| R-03 | Ненадёжные интеграции с табелем/кадровым учётом → рассинхронизация баланса (нарушение AC-01) и пропуск пересечений. |
| R-04 | Несвоевременное уведомление о сгорании → недовольство сотрудников и правовые риски. |
| R-05 | Настраиваемые параметры (коэффициенты, нормы) без валидации → некорректные расчёты. |
| R-06 | Нарушение разграничения доступа (NFR-01) → утечка персональных данных (152-ФЗ). |
| R-07 | Производительность: загрузка баланса более 2 сек при 10 000 сотрудниках. |
| R-08 | Двойной учёт отгулов при пересечениях с отпусками/больничными, если проверки ненадёжны. |
