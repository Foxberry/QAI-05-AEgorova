## Scope

Функциональность «Заявка на больничный лист»: страница личного кабинета сотрудника (раздел «Больничные листы»), позволяющая просматривать данные сотрудника, список ранее поданных больничных листов и сводку по нетрудоспособности за календарный год, оформлять заявление на электронный лист нетрудоспособности (ЭЛН), управлять статусами заявки. Роли: Сотрудник (подаёт заявление), Руководитель (согласует/уведомляется), HR (проверяет и передаёт в расчёт), Администратор (настраивает правила). Правовое основание — оформление ЭЛН в соответствии с законодательством РФ. Учётный период — календарный год.

## Requirements

| ID | Требование |
|----|-----------|
| FR-01 | Система отображает данные сотрудника: ФИО, подразделение, должность, руководитель |
| FR-02 | Система отображает список ранее поданных больничных листов за текущий календарный год: ID документа, дата начала, дата окончания, количество календарных дней, статус заявки |
| FR-03 | Система отображает сводку: количество дней нетрудоспособности за год, количество поданных заявок, статус последней заявки |
| FR-04 | Форма содержит обязательные поля: ID документа больничного листа (номер ЭЛН), дата начала нетрудоспособности, дата окончания нетрудоспособности, тип нетрудоспособности (выпадающий список: заболевание, травма, уход за ребёнком, карантин, прочее) |
| FR-05 | Форма содержит опциональные поля: комментарий сотрудника, прикреплённый файл (скан/справка), отметка «продолжение больничного» со ссылкой на предыдущий ID документа |
| FR-06 | Количество календарных дней рассчитывается автоматически на основании дат начала и окончания, поле недоступно для ручного редактирования |
| FR-07 | Кнопки формы: «Сохранить черновик», «Отправить», «Отмена» |
| FR-08 | Поле «ID документа больничного листа» обязательно для заполнения при отправке заявки |
| FR-09 | Тип поля «ID документа» — строковый |
| FR-10 | Формат и допустимые символы ID соответствуют формату номера ЭЛН (уточняется на этапе внедрения; по умолчанию — цифры, длина фиксирована требованиями СФР) |
| FR-11 | Поле ID проходит проверку на уникальность в системе: один ID не может быть использован в двух заявках |
| FR-12 | При вводе ID система выполняет проверку контрольной суммы / формата (если применимо) и информирует пользователя об ошибке |
| FR-13 | Поле ID не должно содержать персональные данные, не относящиеся к документу |
| FR-14 | При нажатии «Отправить» заявка переходит в статус «На проверке» и направляется в HR |
| FR-15 | При нажатии «Сохранить черновик» заявка сохраняется в статусе «Черновик» и не участвует в расчётах |
| FR-16 | Статусы заявки: Черновик, На проверке, Подтверждён, Отклонён, Отменён |
| FR-17 | HR может подтвердить или отклонить заявку с указанием причины |
| FR-18 | Сотрудник получает уведомление об изменении статуса заявки |
| FR-19 | Подтверждённая заявка передаётся в расчётный модуль / внешнюю систему (СФР, 1С ЗУП и т.п.) для начисления пособия |
| FR-20 | Сотрудник может отменить заявку до её подтверждения |
| FR-21 | Интеграция с внешним сервисом проверки ЭЛН (СФР/ФСС) для валидации ID документа — при наличии технической возможности |
| FR-22 | Интеграция с расчётной системой (1С ЗУП и т.п.) для передачи подтверждённых данных |
| FR-23 | Интеграция с корпоративной почтой / мессенджером для уведомлений |

## Business Rules

| ID | Правило |
|----|---------|
| BR-01 | Дата начала нетрудоспособности не может быть в будущем. Допускается «сегодня» или любая прошедшая дата. При нарушении — блокировка отправки с сообщением «Дата начала больничного не может быть позже текущей даты.» |
| BR-02 | Дата окончания не может быть раньше даты начала |
| BR-03 | Дата окончания не может быть в будущем (для уже закрытого больничного), либо допускается указание плановой даты окончания — уточняется бизнес-правилом |
| BR-04 | ID документа обязателен и должен соответствовать формату |
| BR-05 | ID документа должен быть уникален в системе |
| BR-06 | Заявка не может пересекаться по датам с другим активным больничным листом того же сотрудника |
| BR-07 | Заявка не может пересекаться с уже утверждённым отпуском без явного согласования HR |
| BR-08 | Максимальная длительность одного больничного листа — согласно законодательству (уточняется на этапе внедрения, может варьироваться по типу нетрудоспособности) |
| BR-09 | При указании «продолжение больничного» система проверяет, что предыдущий ID существует, принадлежит сотруднику и его дата окончания +1 день совпадает с датой начала текущего |
| BR-10 | Не допускается подача заявки с датой начала ранее, чем на N дней от текущей даты (например, более 6 месяцев назад) — значение N настраивается администратором |

## Acceptance Criteria

| ID | Критерий |
|----|----------|
| AC-01 | Попытка указать дату начала = завтра → ошибка «Дата начала больничного не может быть позже текущей даты.» |
| AC-02 | Указание даты начала = сегодня → заявка отправляется успешно |
| AC-03 | Отправка заявки без ID документа → ошибка «Укажите ID документа больничного листа.» |
| AC-04 | Ввод ID, который уже использован в другой заявке → ошибка «Больничный лист с таким ID уже зарегистрирован.» |
| AC-05 | Ввод ID неверного формата → ошибка «Неверный формат ID больничного листа.» |
| AC-06 | Дата окончания < даты начала → ошибка «Дата окончания не может быть раньше даты начала.» |
| AC-07 | Пересечение с другим активным больничным → ошибка «Период пересекается с уже зарегистрированным больничным листом.» |
| AC-08 | Отметка «продолжение больничного» с несуществующим предыдущим ID → ошибка |
| AC-09 | Сохранение черновика без обязательных полей → допускается, но отправка невозможна |
| AC-10 | После подтверждения HR заявка уходит в интеграцию и получает статус «Подтверждён» |

## Validation Rules

1. Дата начала ≤ текущей даты (BR-01)
2. Дата окончания ≥ даты начала (BR-02)
3. Дата окончания не в будущем / плановая дата по правилу (BR-03, открытый вопрос)
4. ID обязателен при отправке и соответствует формату (BR-04, FR-08)
5. ID уникален в системе (BR-05)
6. Нет пересечений с активными больничными того же сотрудника (BR-06)
7. Нет пересечений с утверждённым отпуском без согласования HR (BR-07)
8. Длительность ≤ максимума по законодательству (BR-08, открытый вопрос)
9. Для «продолжения больничного»: предыдущий ID существует, принадлежит сотруднику, окончание +1 = начало (BR-09)
10. Дата начала ≥ текущей даты − N дней (BR-10, N настраивается)
11. ID не содержит посторонних персональных данных (FR-13)

## Dependencies

- FR-06 (авторасчёт дней) зависит от корректных дат (BR-02) и формата дат (дд.мм.гггг)
- BR-04, BR-05, FR-12 зависят от определённого формата ID ЭЛН (FR-10, открытый вопрос №1)
- FR-21 (валидация ЭЛН) зависит от доступности внешнего сервиса СФР/ФСС
- BR-06 зависит от данных других заявок сотрудника и перечня статусов «активных» больничных
- BR-07 зависит от данных модуля отпусков
- BR-09 (продолжение) зависит от данных предыдущей заявки сотрудника
- FR-19 (передача в расчёт) зависит от статуса «Подтверждён» (FR-16, FR-17)
- FR-18 (уведомления) зависит от изменения статусов (FR-14, FR-15, FR-17, FR-20)
- FR-22, FR-23 зависят от наличия/доступности внешних систем (открытый вопрос №8)

## Ambiguities

1. **BR-03 плановая дата окончания.** Допускается ли указание плановой даты окончания (открытые больничные) или только закрытые — поведение по умолчанию не задано.
2. **BR-06 «активные больничные».** Перечень статусов, считающихся «активными» для проверки пересечений (Черновик? На проверке? Подтверждён?), не определён.
3. **BR-07 пересечение с отпуском.** Механика «явного согласования HR» не описана: блокировать, предупреждать или автоматически маршрутизировать — варианты не определены (открытый вопрос №5).
4. **BR-08 максимальная длительность.** Значение не задано, зависит от типа нетрудоспособности и законодательства.
5. **BR-10 глубина подачи.** Значение N настраивается администратором, значение по умолчанию (например, 6 месяцев) не зафиксировано.
6. **FR-12 контрольная сумма.** «Если применимо» — не определено, применяется ли проверка контрольной суммы/формата.
7. **FR-13 персональные данные в ID.** Механизм проверки «не содержит персональные данные, не относящиеся к документу» не определён.
8. **FR-10 формат ID.** Точный формат номера ЭЛН (длина, символы, контрольная сумма) не задан — уточняется на этапе внедрения.
9. **FR-05 прикреплённый файл.** Ограничения по формату и размеру файла не заданы.
10. **FR-18/FR-23 канал уведомлений.** Конкретный канал (почта/мессенджер/in-app) не указан.
11. **Типы нетрудоспособности.** Приведён примерный перечень («заболевание, травма, уход за ребёнком, карантин, прочее») — является ли он финальным, не определено.
12. **Отчётность по типам.** Нужно ли разделение по типам нетрудоспособности в отчётности или достаточно одного классификатора (открытый вопрос №6).
13. **Роль Руководителя.** В разделе «Общие положения» Руководитель «согласует/уведомляется», но workflow FR-14 направляет заявку сразу в HR. Нужно ли согласование руководителем, не определено (открытый вопрос №7).
14. **BR-01 vs BR-10.** BR-01 допускает «любую прошедшую дату», BR-10 ограничивает глубину. Взаимодействие правил при не настроенном N не описано.

## Conflicts

1. **BR-01 ↔ BR-10.** BR-01: «допускается … любая прошедшая дата». BR-10: «не допускается подача заявки с датой начала ранее, чем на N дней от текущей даты». Внутреннее противоречие в допустимой глубине ретроспективы при неуточнённом N.
2. **BR-03.** «Дата окончания не может быть в будущем (для уже закрытого больничного)» против «допускается указание плановой даты окончания» — два взаимоисключающих режима без определённого условия выбора.
3. **Роли (Общие положения) ↔ FR-14.** Руководитель «согласует» (раздел 1) vs заявка сразу направляется в HR «На проверку» (FR-14) без шага согласования. Требует решения (открытый вопрос №7).

## Positive Flows

1. Авторизованный сотрудник открывает раздел «Больничные листы» → видит данные сотрудника, список больничных за текущий календарный год и сводку (FR-01, FR-02, FR-03)
2. Сотрудник заполняет форму: ID документа, даты, тип нетрудоспособности → количество дней рассчитано автоматически → «Отправить» → статус «На проверке», заявка направлена в HR (FR-04, FR-06, FR-14)
3. Сотрудник нажимает «Сохранить черновик» → статус «Черновик», в расчётах не участвует (FR-07, FR-15); черновик без обязательных полей допустим (AC-09)
4. HR подтверждает заявку с причиной → статус «Подтверждён», сотрудник уведомлён, заявка передана в расчётную систему (FR-17, FR-18, FR-19, AC-10)
5. Сотрудник отменяет заявку до подтверждения → статус «Отменён» (FR-20)
6. Оформление продолжения больничного: отметка + ссылка на предыдущий ID → проверка BR-09 → отправка успешна
7. Дата начала = сегодня → заявка отправляется успешно (AC-02)

## Negative Flows

1. Дата начала = завтра → ошибка «Дата начала больничного не может быть позже текущей даты.» (BR-01, AC-01)
2. Отправка без ID → ошибка «Укажите ID документа больничного листа.» (BR-04, AC-03)
3. Дубликат ID → ошибка «Больничный лист с таким ID уже зарегистрирован.» (BR-05, AC-04)
4. ID неверного формата → ошибка «Неверный формат ID больничного листа.» (AC-05)
5. Дата окончания < даты начала → ошибка «Дата окончания не может быть раньше даты начала.» (BR-02, AC-06)
6. Пересечение с активным больничным → ошибка «Период пересекается с уже зарегистрированным больничным листом.» (BR-06, AC-07)
7. Пересечение с утверждённым отпуском без согласования HR → блокировка/предупреждение (BR-07, механика не определена)
8. «Продолжение больничного» с несуществующим/чужим предыдущим ID или несовпадением дат → ошибка (BR-09, AC-08)
9. Дата начала ранее, чем N дней от текущей → ошибка (BR-10, N настраивается)
10. Отправка черновика без обязательных полей → невозможна (AC-09)

## Boundaries

1. Дата начала = сегодня → успех (AC-02); = завтра → ошибка (AC-01)
2. Дата окончания = дата начала → 1 календарный день (BR-02)
3. BR-09: дата окончания предыдущего больничного + 1 день = дата начала текущего (граничное условие продолжения)
4. BR-10: дата начала ровно за N дней от текущей — граница допустимости (N настраивается)
5. Максимальная длительность больничного — граница по BR-08 (значение не определено)

## Risks

1. **Высокий:** ошибки валидации ID ЭЛН (формат, контрольная сумма, уникальность) — прямое влияние на правомерность и обработку больничных, риск дублей и мошенничества (BR-04, BR-05, FR-11, FR-12)
2. **Высокий:** пересечения дат (BR-06, BR-07) — конфликт больничных и отпусков, риск некорректных выплат
3. **Высокий:** неопределённость BR-03 (плановая дата окончания) — риск неверной реализации открытых больничных
4. **Высокий:** интеграции (СФР/ФСС, 1С ЗУП, уведомления, FR-21..FR-23) — сбои, потеря данных, задержка выплат
5. **Средний:** персональные данные (NFR-02, 152-ФЗ) — риски утечки при хранении и передаче
6. **Средний:** сложность проверки «продолжения больничного» (BR-09) — риск дефектов в логике связывания
7. **Средний:** ошибки авторасчёта дней (FR-06) при високосных годах и граничных датах
8. **Средний:** неоднозначность статусов «активных» больничных (BR-06) и глубины подачи (BR-10) — риск неверной реализации
