## Suite 1. Доступ и отображение информации

### TC-01 — Доступ авторизованного сотрудника к странице «Больничные листы»
- **Source:** Общие положения (Доступ), FR-01
- **Priority:** HIGH | **Type:** positive
- **Preconditions:** Авторизованный сотрудник имеет доступ к личному кабинету.
- **Steps:** 1. Авторизоваться. 2. Открыть личный кабинет → раздел «Больничные листы».
- **Expected Result:** Страница «Заявка на больничный лист» открывается без ошибок.

### TC-02 — Отображение данных сотрудника
- **Source:** FR-01
- **Priority:** MEDIUM | **Type:** positive
- **Preconditions:** Сотрудник авторизован, данные в системе заполнены.
- **Steps:** 1. Открыть раздел «Больничные листы». 2. Проверить блок данных сотрудника.
- **Expected Result:** Отображаются ФИО, подразделение, должность и руководитель.

### TC-03 — Отображение списка больничных листов за текущий календарный год
- **Source:** FR-02
- **Priority:** HIGH | **Type:** positive
- **Preconditions:** За текущий календарный год у сотрудника есть несколько больничных листов.
- **Steps:** 1. Открыть раздел «Больничные листы». 2. Проверить список.
- **Expected Result:** Список за текущий календарный год содержит ID документа, дату начала, дату окончания, количество календарных дней и статус каждой заявки.

### TC-04 — Отображение сводки по нетрудоспособности
- **Source:** FR-03
- **Priority:** MEDIUM | **Type:** positive
- **Preconditions:** У сотрудника есть поданные больничные листы.
- **Steps:** 1. Открыть раздел «Больничные листы». 2. Проверить блок сводки.
- **Expected Result:** Отображаются: количество дней нетрудоспособности за год, количество поданных заявок, статус последней заявки.

### TC-05 — Доступ неавторизованного пользователя (QA/Risk-based)
- **Source:** Общие положения (Доступ)
- **Priority:** HIGH | **Type:** risk-based
- **Preconditions:** Пользователь не авторизован.
- **Steps:** 1. Попытаться открыть раздел «Больничные листы» без авторизации.
- **Expected Result:** Доступ запрещён: выполняется перенаправление на авторизацию либо отображается ошибка доступа. (Поведение уточняется реализацией.)

## Suite 2. Форма оформления больничного листа

### TC-06 — Форма содержит обязательные и опциональные поля
- **Source:** FR-04, FR-05
- **Priority:** HIGH | **Type:** positive
- **Preconditions:** Открыт раздел «Больничные листы», сотрудник нажал «Новая заявка».
- **Steps:** 1. Открыть форму оформления. 2. Проверить состав полей.
- **Expected Result:** Присутствуют обязательные поля: ID документа, дата начала, дата окончания, тип нетрудоспособности; опциональные: комментарий, прикреплённый файл, отметка «продолжение больничного».

### TC-07 — Количество дней рассчитывается автоматически и не редактируется
- **Source:** FR-06
- **Priority:** HIGH | **Type:** positive
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Выбрать дату начала и окончания. 2. Попытаться изменить поле «Количество календарных дней» вручную.
- **Expected Result:** Поле заполняется автоматически на основании дат и недоступно для ручного редактирования.

### TC-08 — Кнопки формы «Сохранить черновик», «Отправить», «Отмена»
- **Source:** FR-07
- **Priority:** MEDIUM | **Type:** positive
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Проверить наличие кнопок. 2. Убедиться, что кнопки активны.
- **Expected Result:** Присутствуют и активны кнопки «Сохранить черновик», «Отправить», «Отмена».

### TC-09 — Отправка формы с незаполненными обязательными полями (QA/Risk-based)
- **Source:** FR-04
- **Priority:** HIGH | **Type:** risk-based
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Не заполнять обязательные поля. 2. Нажать «Отправить».
- **Expected Result:** Система блокирует отправку и подсвечивает обязательные поля; заявка не создаётся.

### TC-10 — Тип нетрудоспособности выбирается из выпадающего списка
- **Source:** FR-04
- **Priority:** MEDIUM | **Type:** positive
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Открыть выпадающий список «Тип нетрудоспособности».
- **Expected Result:** Доступны значения: заболевание, травма, уход за ребёнком, карантин, прочее. (Перечень подтверждается владельцем требований — Ambiguity #11.)

## Suite 3. Поле ID документа больничного листа

### TC-11 — Отправка заявки без ID документа
- **Source:** BR-04, AC-03
- **Priority:** HIGH | **Type:** negative
- **Preconditions:** Открыта форма оформления, все поля заполнены, кроме ID.
- **Steps:** 1. Оставить поле ID пустым. 2. Нажать «Отправить».
- **Expected Result:** Ошибка «Укажите ID документа больничного листа.»; заявка не отправляется.

### TC-12 — Дубликат ID документа
- **Source:** BR-05, AC-04
- **Priority:** HIGH | **Type:** negative
- **Preconditions:** ID уже используется в другой заявке в системе.
- **Steps:** 1. Ввести ID, уже использованный в другой заявке. 2. Нажать «Отправить».
- **Expected Result:** Ошибка «Больничный лист с таким ID уже зарегистрирован.».

### TC-13 — ID неверного формата
- **Source:** AC-05, FR-12
- **Priority:** HIGH | **Type:** negative
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Ввести ID, не соответствующий формату номера ЭЛН (например, с буквами/неверной длиной). 2. Нажать «Отправить».
- **Expected Result:** Ошибка «Неверный формат ID больничного листа.».
- **Blocker:** точный формат ЭЛН не определён (Open Question №1) — сценарий зависит от решения по формату.

### TC-14 — ID корректного формата принимается
- **Source:** FR-08, FR-10, FR-12
- **Priority:** HIGH | **Type:** positive
- **Preconditions:** Открыта форма оформления, формат ЭЛН подтверждён.
- **Steps:** 1. Ввести ID корректного формата (цифры, фиксированная длина). 2. Нажать «Отправить».
- **Expected Result:** ID проходит проверку формата, ошибок нет.
- **Blocker:** зависит от подтверждения формата ЭЛН.

### TC-15 — ID не содержит посторонних персональных данных (QA/Risk-based)
- **Source:** FR-13
- **Priority:** MEDIUM | **Type:** risk-based
- **Preconditions:** Открыта форма оформления.
- **Steps:** 1. Ввести в поле ID текст, содержащий посторонние персональные данные (например, ФИО).
- **Expected Result:** Форматная валидация отклоняет значение (недопустимые символы); либо система предупреждает. (Механика проверки FR-13 не определена — Ambiguity #7.)

## Suite 4. Валидации дат и пересечений
